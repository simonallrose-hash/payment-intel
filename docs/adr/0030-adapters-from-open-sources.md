# ADR-0030 — Адаптеры платформ только из открытых исходников витрины

Статус: принято (долг этапов 2–4). Связано: FR-CW-03, FR-CW-04, ADR-0014, ADR-0029.

## Контекст

После этапа 4 адаптеры были у пяти платформ (WooCommerce, Magento 2,
Shopware 6, PrestaShop, Shopify); остальные платформы справочника шли
эвристикой. Правило проекта: каждый селектор адаптера должен быть сослан
на источник, который можно проверить, — иначе он не отличается от
«подсмотренного» на живом магазине и ломается без предупреждения.

## Решения

1. **Пять новых адаптеров — OpenCart, OXID eShop, Shopware 5, Magento 1
   (OpenMage), BigCommerce (Cornerstone)** — собраны только по открытым
   исходникам витрины: репозитории платформ на GitHub (`opencart/opencart`
   4.x, `OXID-eSales/wave-theme` b-7.0.x, `shopware5/shopware` 5.7,
   `OpenMage/magento-lts`, `bigcommerce/cornerstone`). В докстринге каждого
   адаптера перечислены файлы шаблонов, из которых взяты пути, имена полей
   и селекторы. Сторонние темы могут отличаться классами, поэтому адаптер
   опирается прежде всего на пути (`index.php?route=checkout/cart`,
   `index.php?cl=basket`, `/checkout/confirm`, `/checkout/onepage/`,
   `/cart.php`) и имена полей формы, которые задаёт платформа.
2. **plentymarkets и JTL-Shop остаются на эвристике.** Шаблоны витрины
   plentymarkets (Ceres) и JTL (NOVA) не удалось прочитать из первоисточника:
   репозиторий JTL живёт на GitLab, чей `robots.txt` запрещает наш обход,
   а API GitHub/GitLab из среды недоступны. Селекторы из вторичных
   источников в адаптер не переносятся (правило самопроверки проекта).
3. **Текст метки для чекбоксов и радиокнопок.** Описание контрола для
   политики кликов (`DESCRIBE_CONTROL_JS`) берёт текст из связанных
   `<label>` (`el.labels`), когда у самого элемента текста нет: иначе
   чекбокс «Kein Kundenkonto erstellen» (Shopware 5) выглядел как
   неизвестная кнопка и срабатывал стоп `guardrail_ambiguous_button`.
   Словарь `guest_checkout` (de) пополнен фразами «kein kundenkonto
   erstellen / anlegen». Политика кликов не ослаблялась (ADR-0013).
4. **Симулятор** получил flavour на каждую новую платформу с разметкой из тех
   же исходников (`tests/e2e/shopsim.py`: `product_item_class`,
   `cart_item_attrs`, `checkout_link_attrs`), а e2e-проход до шага оплаты
   параметризован по 11 магазинам. Реестр адаптеров проверяется юнит-тестом:
   у каждого есть `platform_ids`, селектор добавления в корзину, путь или
   ссылки корзины и чекаута.

## Последствия

- 10 адаптеров из 21 платформы справочника; остальные — эвристика
  (`adapter="heuristic"` в `obs_scan`).
- Прогон по реальным магазинам каждой платформы остаётся долгом (нет
  согласованного списка целей).
