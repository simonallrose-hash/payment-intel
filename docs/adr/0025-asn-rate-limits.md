# ADR-0025 — Лимиты скорости по ASN после жалоб хостеров и таблица ip2asn

Статус: принято (этап 4). Связано: FR-OO-04, FR-SC-04, FR-LS-02, LR-02, ADR-0010.

## Решения

1. **Единица ограничения — ASN, не домен.** Жалоба хостера касается его
   сети; лимит `asn_limit` действует для всех хостов, чьи IP принадлежат
   ASN: per-host и per-IP скорости умножаются на `factor` (0.1 по
   умолчанию), и вводится один общий bucket `asn:<asn>` на всю сеть
   (`asn_rps`, 1 запрос/с). Повторная жалоба делит `factor` пополам
   (не ниже 0.01); снятие — только `staff_admin` после разбора, с
   аудитом. Пока жалоба не снята, лимит не истекает.
2. **IP → ASN из таблицы оператора.** Базы ASN в репозитории нет
   (ADR-0023 §3); оператор кладёт TSV iptoasn.com (PDDL, обновляется
   ежечасно, `AS 0` = не маршрутизируется) и указывает
   `PAYINTEL_SCAN__ASN_TABLE_PATH`. Та же таблица заполняет `host.asn` и
   `hosting_country` при резолве (FR-DS-05). Без таблицы жалоба принимается
   только по номеру ASN (`AS12345`), не по IP, а воркеры не применяют
   лимиты по ASN (это написано в логе при старте).
3. **Воркеры перечитывают лимиты каждые 60 с** (`AsnPolicy.refresh`), без
   рестарта; жалоба действует «сразу» в этом смысле — самое позднее через
   минуту на каждом воркере.
4. **Приём жалоб — CLI и админка**, без почтового парсера: источник
   (`abuse@`-письмо, форма, тикет) и заметка хранятся в строке лимита для
   отчётности; пакетный импорт — файл строк `TARGET<TAB>SOURCE[<TAB>NOTE]`.
