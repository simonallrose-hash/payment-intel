# ADR-0029 — Адаптер Shopify: только документированная витрина, чекаут — эвристикой

Статус: принято (этап 4). Связано: FR-CW-03, FR-CW-04, ADR-0014.

## Решения

1. **Селекторы витрины — из темы Dawn** (эталонная тема Online Store 2.0,
   открытый исходник): ссылки `/products/<handle>`, форма товара с
   `action$="/cart/add"` и кнопкой `button[type=submit][name="add"]`,
   корзина `/cart` с `button#checkout[name="checkout"]`, чекаут `/checkout`.
   Сторонние темы отличаются классами, но пути и имена полей формы
   задаются платформой, поэтому адаптер опирается на них.
2. **Чекаут Shopify не документирован** и не является темой; его разметка
   в адаптер **не переносится**. Поля ищутся по стандартным токенам
   `autocomplete` с префиксом секции (`shipping given-name`) оператором
   `~=`, блок оплаты и радиокнопки — эвристикой. Так адаптер не ломается
   при смене вёрстки чекаута и не содержит «подсмотренных» селекторов,
   которые нельзя сослать на источник (правило самопроверки проекта).
3. **Чекаут на чужом хосте не проходится.** Чекаут Shopify с 2017-07-20
   идёт на домене магазина (`/<id>/checkouts/<token>`, см. ADR-0032), так
   что для Shopify исключений не нужно; магазин, уводящий с eTLD+1 (например,
   на `*.myshopify.com` при принудительном редиректе на основной домен),
   останавливается по правилам ADR-0032 — осознанно, чтобы не расширять
   область действия прохода на хосты вне согласованной идентичности
   (ADR-0014).
4. **Симулятор получил flavour `shopify`** и e2e-проход до шага оплаты;
   прогон по реальным магазинам Shopify остаётся долгом (как и для
   остальных платформ, см. отчёт этапа 4).
