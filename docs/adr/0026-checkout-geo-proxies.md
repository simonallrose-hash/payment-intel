# ADR-0026 — Гео-параметр прохода и прокси только для геолокации

Статус: принято (этап 4). Связано: FR-CW-11, FR-CW-05, LR-02, LR-03, ADR-0014.

## Решения

1. **Страна прохода = страна магазина.** Локаль, `Accept-Language` и
   синтетический адрес идентичности берутся из страны магазина
   (FR-CW-05) и записываются как `checkout_country`; это уже было, FR-CW-11
   добавляет сетевую часть.
2. **Прокси — только если страна магазина ≠ страна egress.** Оператор
   задаёт `PAYINTEL_CHECKOUT__EGRESS_COUNTRY` и словарь
   `PAYINTEL_CHECKOUT__GEO_PROXIES` (`{"FR": "http://user:pass@host:port"}`,
   схемы http/https/socks5). Решение принимается **один раз до прохода**
   (`geo.choose`), результат попадает в журнал и манифест без учётных
   данных (`geolocation_proxy` / `egress_country` / `no_proxy_for_country`).
   Без прокси для страны проход всё равно идёт с языком и адресом страны.
3. **Что не делается (LR-03).** Прокси не применяется в ответ на блокировку,
   429 или гео-отказ; ротации нет; User-Agent, robots и politeness те же.
   Прокси задаётся на контекст браузера (`browser.new_context(proxy=…)`),
   а не на запуск: воркеры работают в Linux-контейнере, где Playwright не
   требует запуска Chromium с `proxy={"server": "per-context"}` (это
   нужно только на Windows).
4. **Проверка пройденной геолокации не делается.** Система не проверяет,
   что прокси действительно «в стране»: это ответственность оператора,
   выбравшего поставщика; в манифесте есть хост прокси для разбора.
