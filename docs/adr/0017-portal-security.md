# ADR-0017 — Портал и админка: серверные сессии, CSP без inline, без HTMX/Tailwind с CDN

Статус: принято (этап 3). Связано: FR-UI-01…06, FR-ADM-01…07, NFR-S-03, NFR-S-05.

## Контекст

ТЗ требует обязательный TOTP, idle-таймаут 12 ч, CSRF, SameSite=Strict,
CSP без `unsafe-inline`, lockout 10 попыток / 15 мин. ТЗ упоминает HTMX и
Tailwind как возможный стек UI. В среде сборки внешние CDN недоступны, а
поставлять фронтенд-зависимости «вслепую» (без проверки хэшей) противоречит
NFR-S-10.

## Решения

1. **Серверный рендеринг Jinja2 + один статический CSS** (`api/static/app.css`,
   ~250 строк). Никакого JavaScript: все действия — обычные формы с POST и
   редиректом 303. Это даёт CSP `default-src 'none'; script-src 'self';
   style-src 'self'; img-src 'self' data: https:; form-action 'self';
   frame-ancestors 'none'; base-uri 'none'` без `unsafe-inline`
   (`script-src 'self'` оставлен для вендоренных скриптов позже; сейчас ни
   одного `<script>` в шаблонах нет). HTMX/Tailwind можно добавить позже как локально
   вендоренные файлы с SRI; архитектура от этого не меняется.
2. **Сессии — на сервере.** Cookie `pi_session` содержит случайный 32-байтовый
   токен; в БД (`portal_session`) — его SHA-256, владелец, CSRF-токен,
   `last_seen_at`, `totp_verified`. Idle-таймаут 12 ч проверяется и продлевается
   на каждом запросе; выход и смена пароля отзывают сессию. Cookie:
   `HttpOnly; SameSite=Strict; Secure` (в dev `Secure` выключается настройкой
   `api.cookie_secure`).
3. **Вход в два шага.** Пароль (argon2id) → сессия со статусом «pending» →
   обязательный TOTP (при первом входе — энролмент с QR-URI; секрет хранится
   в AES-GCM с `user.id` как associated data) → `totp_verified=true`. Без
   второго шага открываются только страницы входа.
4. **CSRF.** Токен на сессию, скрытое поле `csrf` в каждой форме, сравнение
   `hmac.compare_digest`. Для форм входа (сессии ещё нет) — проверка
   `Origin`/`Referer` на совпадение хоста.
5. **Lockout.** 10 неудачных попыток → блокировка на 15 минут (счётчик на
   пользователе, сбрасывается при успехе). Ответ на неверный пароль и на
   несуществующий e-mail одинаков.
6. **Роли.** `org_admin` (ключи, пользователи, watchlists, экспорты),
   `org_viewer` (только чтение); staff: `staff_admin`, `staff_support`
   (только чтение), `staff_compliance` (KYC, контракты, entitlements,
   opt-out/DSAR, approve экспортов), `staff_analyst` (правила, домены C1,
   отчёты). Матрица проверяется в `tests/stage3/test_portal_ui.py`.
7. **Ошибки.** На UI-путях исключения рендерятся HTML-страницей ошибки;
   снимок `csrf`/`email` берётся при создании контекста, так как ORM-строки
   к моменту рендера уже откачены.

## Последствия

- Нет клиентской интерактивности (автодополнение, живой поиск) — для
  этапа 3 это допустимо; весь функционал доступен формами.
- Статика отдаётся приложением; Caddy кэширует её `Cache-Control` по пути
  `/static/`.
