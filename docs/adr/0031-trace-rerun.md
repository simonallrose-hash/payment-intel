# ADR-0031 — Повторный проход с трассировкой Playwright из админки (FR-QA-06)

Статус: принято (долг этапа 4). Связано: FR-QA-06, FR-ADM-*, ADR-0014, ADR-0017.

## Контекст

Разбор остановок (FR-QA-06) опирался на скриншот и DOM в момент стопа.
Для сложных случаев (многошаговые чекауты, JS-редиректы, гонки загрузки)
этого мало: нужна покадровая запись прохода. Playwright умеет писать трейс
(скриншоты + снимки DOM + сетевые события), но запись дорога и не должна
включаться для всех проходов.

## Решения

1. **Флаг на плане, а не на хосте.** `scan_plan.trace_requested` (bool) и
   `scan_plan.requested_by` ставятся ручной приоритизацией
   (`planner.prioritize_manual(..., trace=True)`) только для `scan_type =
   checkout`; лёгкие планы флаг не получают. Лизинг переносит флаг в
   `WalkInput.trace`; после прохода воркер сбрасывает флаг и автора, так что
   трейс пишется ровно один раз (`_reschedule`).
2. **Запись.** `context.tracing.start(screenshots=True, snapshots=True,
   sources=False)` сразу после создания контекста; остановка — до закрытия
   контекста, в zip во временном файле; ошибки записи не валят проход
   (журнал `trace: unavailable`). Исходники скриптов не пишутся (`sources=False`):
   это чужой код.
3. **Хранение и доступ.** Zip лежит рядом с артефактами прохода:
   `checkout/<etld1>/<run_id>/trace.zip` (ключ в `scan_run.trace_key` и
   `manifest.trace_key`), lifecycle бакета 90 дней (LR-08). Скачивание —
   `GET /admin/domains/{host}/runs/{run_id}/trace` для `staff_analyst` и
   выше, просмотр — `playwright show-trace trace.zip`. В C1 и экспорты
   трейс не попадает (AS-23).
4. **Запуск.** Форма «Re-run checkout walk» на странице домена в админке
   (CSRF, чекбокс «с трейсом», действие в `audit_log` как
   `scan_plan.prioritize` с `trace`) и CLI `payintel scheduler prioritize
   <host> --scan-type checkout --trace`. Для opt-out и доменов вне тяжёлого
   скана перезапуск не ставится (проверка планировщика не обходится).
5. **Миграция** `0012_trace_rerun`: три nullable/default-колонки, без
   обратной несовместимости.

## Последствия

- Трейс содержит снимки DOM страниц магазина с подставленными синтетическими
  данными; персональных данных третьих лиц там нет (identity синтетическая),
  но доступ ограничен ролями staff.
- Размер трейса одного прохода — единицы мегабайт; массовое включение не
  предусмотрено по дизайну (флаг только через ручной запрос).
