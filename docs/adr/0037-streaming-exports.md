# ADR-0037: Потоковая сборка выгрузок с внешней сортировкой

Статус: принято (долг 5, 2026-10-12). Связано: NFR-P-06, FR-EX-05, AC-12,
ADR-0034, ADR-0036.

## Контекст

Выгрузка (FR-EX-*) собиралась целиком в памяти: `builder.*_rows` возвращал
список словарей на все строки, `watermark.order_rows` сортировал его по
ключу водяного знака, `write_parquet` кодировал в `BytesIO`, `put_bytes`
отправлял байты. На полном снимке 1 млн магазинов (стенд ADR-0034) пик
памяти экспортёра — 3,2 ГБ, лимит контейнера пришлось поднять до 4 ГБ
(capacity.md §3), а рост до потолка AS-11 (3 млн магазинов) упёрся бы в
память, не в время.

Отказаться от сортировки нельзя: порядок строк и есть водяной знак
(FR-EX-05) — `SHA-256(watermark_id || ключ строки)`, по нему утёкший файл
сопоставляется с выгрузкой даже без метаданных.

## Решение

1. **Строки идут потоком.** `builder.iter_snapshot_rows` и
   `iter_increment_rows` — генераторы (страница из 5 000 магазинов с их
   join'ами в памяти за раз); списковые `snapshot_rows`/`increment_rows`
   остались обёртками.
2. **Внешняя сортировка слиянием** — `exports/stream.py::SpillSorter`.
   Строки накапливаются порциями `export.rows_per_chunk` (50 000); полная
   порция сортируется по ключу и пишется во временный файл (pickle, один
   объект на строку); итерация сливает файлы `heapq.merge` по ключу — в
   памяти одна порция плюс по одной строке на файл. Ключи сравниваются
   только между собой (одинаковые ключи не приводят к сравнению словарей).
3. **Файл пишется на диск по row-group'ам** (`write_parquet_to` с путём или
   файловым объектом, `write_csv_to` в текстовый поток) и **загружается
   файлом** (`ObjectStore.put_file` → `upload_file`, multipart выше 8 МБ),
   а не байтами из памяти.
4. **Рабочий каталог на диске.** `export.scratch_dir`
   (`PAYINTEL_EXPORT__SCRATCH_DIR`, пусто = системный temp) — на экспортёре
   это том `exporter-scratch:/var/tmp/payintel`: корневая ФС контейнера
   read-only, а `/tmp` — tmpfs, где «на диск» означало бы «в память».
   Каталог создаётся в образе с владельцем `payintel`. Временные файлы
   удаляются по выходу из контекста, в том числе при ошибке.
5. Проверки квоты и лимита строк (`export_max_rows`, одобрение) делаются по
   точному числу собранных строк до записи файла, как раньше; `job.rows`
   и `usage_log` не меняются по смыслу.

## Последствия

- Пик памяти экспортёра не зависит от размера выгрузки: порция 50 000
  строк (~160 МБ словарей) + буферы Arrow одной row-group; число для стенда
  1 млн — в capacity.md §3 и в ночном bench.yml (`scripts/bench_export.py`
  печатает пик RSS). Диск: временные порции ≈ объём строк в pickle плюс
  готовый файл; на 1 млн строк это сотни мегабайт, том `exporter-scratch`
  должен их вмещать.
- Тесты: `tests/unit/test_export_stream.py` (сброс на диск, слияние,
  повторяемость порядка, пустая выгрузка, равные ключи, потоковые
  писатели), `tests/stage3/test_exports.py::
  test_snapshot_export_spills_to_disk_when_rows_exceed_a_chunk` (порция 2
  строки → каждая порция на диске, порядок водяного знака сохранён,
  каталог пуст после загрузки), `tests/integration/test_s3.py::
  test_put_file_uploads_large_files_in_multipart` (20 МиБ в SeaweedFS).
- Формат файлов, метаданные и порядок строк не изменились; `read_rows`,
  `order_matches` и бенч `bench_export.py` работают как прежде.
