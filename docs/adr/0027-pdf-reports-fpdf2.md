# ADR-0027 — PDF-отчёты: fpdf2 вместо WeasyPrint + matplotlib

Статус: принято (этап 4). Связано: FR-RP-04, FR-RP-01…03, AS-25.

## Решения

1. **fpdf2, не WeasyPrint.** ТЗ называет WeasyPrint + matplotlib; WeasyPrint
   требует системных библиотек (Pango, Cairo, GDK-Pixbuf), что ломает
   воспроизводимость сборки и CI, а matplotlib тянет NumPy ради десятка
   столбчатых диаграмм. fpdf2 — чистый Python, детерминированный вывод,
   тест проверяет текст через pypdf. Отклонение зафиксировано в отчёте
   этапа; возврат к WeasyPrint возможен заменой `reports/pdf.py`, вход тот
   же `Report`.
2. **Диаграммы — прямоугольники fpdf2**: горизонтальные столбцы долей с
   95 % интервалом Уилсона линией, топ-10 строк на ячейку плюс `other`.
   Этого достаточно для FR-RP-04 («графики»), без растров.
3. **Шрифты — DejaVu Sans в репозитории** (лицензия Bitstream Vera в
   `reports/fonts/LICENSE`): кириллица и типографские тире в методологии
   рендерятся без системных шрифтов.
4. **PDF строится вместе с XLSX/CSV** при каждом `report build`
   (`reports/{id}.pdf`), скачивается из админки и портала той же
   организацией, что получила отчёт; отдельного «PDF по запросу» нет.
