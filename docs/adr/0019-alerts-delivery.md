# ADR-0019 — Алерты: доставка, подпись, ретраи, дайджесты

Статус: принято (этап 3). Связано: FR-AL-01…05, AS-19, ADR-0007, AC-09.

## Решения

1. **Источник событий — `change_event`**, уже прошедший правило «два
   подтверждения подряд» (ADR-0015). Матчер (`alerts.matcher`) читает события
   по курсору (`alert_cursor`), сопоставляет с правилами организаций по
   watchlist-домену, типу события, провайдеру/методу и минимальной
   уверенности; события невидимых доменов (CZDS-only, opt-out) не
   доставляются никогда.
2. **Каналы — webhook и Telegram** (без e-mail, ADR-0007). Webhook: POST
   JSON, заголовок `X-PayIntel-Signature: t=<unix>,v1=<hmac-sha256(secret,
   "<t>." + body)>`, допуск ±300 с. Секрет `whsec_…` показывается один раз,
   хранится в AES-GCM. Telegram: Bot API `sendMessage` в чат, привязанный в
   портале.
3. **Ретраи.** До 5 попыток с задержками 1, 3, 7, 13 ч (сумма ≤ 24 ч,
   FR-AL-04); 2xx — доставлено, иное — следующая попытка; после 5 — `failed`,
   видно в портале. HTTP-клиент не следует редиректам и не ходит на приватные
   адреса (проверка IP как у краулера).
4. **Дайджесты.** `digest = immediate | daily | weekly` на правило; дайджест
   собирает все совпадения с последней отправки в одно сообщение в
   `alerts.digest_hour_utc`. Команда `alerts dispatch --force-digests` для
   ручного запуска.
5. **Идемпотентность.** `alert_delivery` уникальна по (rule, event); повторный
   цикл не создаёт дублей; `event_id` присутствует в теле webhook.
