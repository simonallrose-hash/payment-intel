# ADR-0020 — Правила детекции в админке: версии, наложение на YAML, предпросмотр

Статус: принято (этап 3). Связано: FR-ADM-02, FR-DT-01, FR-DT-07, FR-QA-02.

## Решения

1. **YAML остаётся источником правды для релиза,** БД — для оперативных
   правок. `detection_rule` хранит все версии; `seed` загружает YAML как
   `source_file=<путь>`, правки из админки сохраняются новой версией с
   `source_file="admin"`. Эффективный набор — `detect.admin.overlay(yaml)`:
   для каждого `rule_id` побеждает большая версия, а правка из админки —
   всегда (чтобы отключённое правило не «воскресло» после `seed`).
2. **Включение/выключение — тоже версия.** `set_enabled` пишет новую версию
   с `enabled=false`; удалений нет (аудит FR-AB-01, FR-DT-07:
   `ruleset_version` сканов меняется).
3. **Предпросмотр на gold set.** Перед сохранением аналитик видит precision/
   recall черновика по наблюдениям gold-магазинов из ClickHouse
   (`obs_provider`, `obs_payment_method`, `obs_tech` — те же сигналы, что
   видел движок), без запуска сканов. Это оценка одного правила, а не всего
   ансамбля, что написано на странице.
4. **Воркеры** читают `overlay` при старте и по сигналу перезагрузки;
   `rules-check` в CI валидирует YAML, тест `test_rule_admin.py` — наложение.
