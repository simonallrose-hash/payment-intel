# ADR-0038: Сторонние скрипты скачивает отдельный пул, по URL и один раз

Статус: принято (долг 6, 2026-10-12). Уточняет ADR-0011 п. 1. Связано:
FR-LS-03, FR-SC-06, FR-LS-05, LR-08.

## Контекст

FR-LS-03: «внешние JS-файлы скачиваются один раз и дедуплицируются по
SHA-256; хранится связь „хэш → хосты“». ADR-0011 оставил скачивание только
первосторонним скриптам: хост CDN (`js.stripe.com`, `cdn.shopify.com`) общий
для тысяч магазинов, и при честном лимите 1 запрос/с на хост (FR-SC-06)
каждый скан, ждущий свою очередь к CDN, превращал его в общую очередь парка
(на нагрузочном прогоне время скана выросло с 6 до 100+ с). Строка FR-LS-03
в матрице оставалась «частично».

Причина затора — не лимит, а то, что скан *ждал* чужой хост и качал один и
тот же файл тысячи раз. Файл по фиксированному URL нужен один раз; магазинов,
ссылающихся на него, — тысячи, и им достаточно связи с хэшем.

## Решение

1. **Скан не качает сторонние скрипты и не ждёт их.** В сетевой фазе
   `LightScanner` только собирает URL скриптов с чужих eTLD+1
   (`scripts.third_party_script_urls`: http(s), без фрагмента, с query —
   она версионирует файлы CDN; не более `light.max_third_party_scripts` = 25
   на скан). URL по-прежнему сигналы для правил (`script_src`,
   `network_host`) — детекция не зависит от загрузки.
2. **Фаза записи** (`scripts.record_script_requests`, в той же транзакции,
   что `scan_run`): для каждого URL — строка `js_asset_url` (PK — URL).
   Если тело уже скачано и свежо (`status=ok`, `next_fetch_at` в будущем) —
   хост сразу привязывается к хэшу (`host_js_asset`). Если строки нет —
   она создаётся как `pending`; если тело устарело — строка снова `pending`,
   но хэш сохраняется и хост привязывается к последнему известному телу.
   Хост, которому нужно ещё не скачанное тело, ждёт в `js_asset_url_host`.
3. **Пул скриптов** (`scripts.fetch_script_urls`) — фоновый проход
   `worker-light` раз в `light.third_party_js_interval_seconds` (30 с) и
   ещё раз перед остановкой; тот же проход — `payintel scripts fetch`.
   Берёт до `third_party_js_batch` (200) просроченных URL
   `FOR UPDATE SKIP LOCKED` (несколько воркеров не качают один URL дважды),
   качает тем же `Fetcher` — лимиты 1 rps на хост / 5 rps на IP, egress-фильтр
   и 2 МБ на файл действуют как для любого запроса, но ждёт в очереди к CDN
   только пул, а не сканы. Тело → S3 `js/<aa>/<sha256>.js.gz`, строка
   `js_asset`, все ждущие хосты → `host_js_asset`, ожидание удаляется.
4. **Один раз, с проверкой.** Скачанный URL получает `next_fetch_at = now +
   light.third_party_js_ttl_days` (7); до этого срока новые ссылки на него
   обходятся без сети. Ошибка (не 200, обрезка, таймаут, egress) —
   `attempts += 1`, повтор через `attempts × 1 ч`; после
   `third_party_js_max_attempts` (3) URL паркуется как `error` на срок TTL,
   ждущие хосты остаются до удачной загрузки.
5. **Связь «хэш → хосты»** — таблица `host_js_asset`, общая для первосторонних
   и сторонних скриптов; `js_asset_url` добавляет «URL → хэш» и состояние
   загрузки. Записи `js_asset`/`host_js_asset` — upsert: два скана, увидевшие
   одно тело одновременно, раньше падали на первичном ключе.

## Последствия

- Пропускная способность сканов не зависит от CDN: на скан добавляются
  только записи в БД (до 25 строк); замер — capacity.md §3 / отчёт долга 6.
- Сеть к CDN: число запросов = число различных URL (а не сканов) раз в
  7 дней; 1 rps на хост соблюдается пулом.
- Попутно исправлен разбор атрибутов HTML: `&currency=EUR` в `src` больше не
  превращается в `¤cy=EUR` (`html.unescape` декодирует устаревшие сущности
  без `;`, браузер в атрибуте — нет; `html._browser_attrs`). Это влияло и на
  сигналы `script_src` для правил FR-LS-05.
- Наблюдаемость: `payintel scripts status` (URL по статусам, ждущие хосты),
  метрика `payintel_js_fetch_total{result}`, лог `script pool pass`.
- Тела скриптов хранятся в `js/` без срока (как и первосторонние); они не
  содержат персональных данных, LR-08 касается HTML. Тесты:
  `tests/unit/test_light_scripts.py`, `tests/integration/test_light_worker.py::
  test_scan_records_third_party_script_urls_without_fetching_them`,
  `::test_script_pool_fetches_each_url_once_and_links_every_host`.
