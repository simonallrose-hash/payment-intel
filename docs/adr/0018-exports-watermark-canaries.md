# ADR-0018 — Экспорты: водяной знак, канарейки, лимиты и формат

Статус: принято (этап 3). Связано: FR-EX-01…06, FR-AB-04, LR-17, AC-08.

## Решения

1. **Два задания в одном пайплайне.** `export_job` создаётся клиентом
   (`POST /v1/exports`, портал) или планировщиком (`exports run`:
   периодические экспорты по `entitlement.export_schedule`). Полные снимки
   требуют одобрения `staff_compliance` (`awaiting_approval → pending`), дельты
   и выборки по watchlist строятся сразу. Файл кладётся в S3
   `exports/<org>/<job>.<fmt>`, ссылка подписана на 72 ч, повторная выдача
   ссылки — новая подпись на тот же объект.
2. **Водяной знак = порядок строк.** Строки сортируются по
   `SHA-256(watermark_id || domain)`; `watermark_id` хранится в `export_job`
   и в метаданных файла (Parquet key-value metadata, первая строка-комментарий
   `# payintel export=… watermark=…` в CSV, поле `_meta` первой строки JSONL).
   Если метаданные вырезаны, порядок строк всё ещё позволяет сопоставить
   файл с экспортом (`exports.watermark.order_matches`).
3. **Канарейки.** В каждый экспорт добавляются 3–10 синтетических магазинов
   `c-<12 hex>.<canary zone>` (число детерминировано от id экспорта); домены
   под контролем компании, таблица `canary` связывает домен с организацией и
   экспортом. Обращение к такому домену атрибутируется утечке.
4. **Лимиты.** `export_max_rows` из entitlement; превышение → 403
   `export_limit_exceeded` до построения. Экспорт учитывается в суточной
   квоте записей.
5. **Профили.** Экспорт использует те же Pydantic-схемы, что и API
   (`StoreBasic`/`StoreFull`), поэтому поля C1 отсутствуют физически.
   Домены CZDS-only и opt-out исключены тем же предикатом, что и в API.
6. **CSV-комментарий.** Первая строка CSV начинается с `#` — стандартные
   читалки (pandas `comment="#"`, Excel) её игнорируют; это задокументировано
   в `docs/api.md`.
