# ADR-0016 — API /v1: entitlements, сегменты, 403 vs 404, подавление малых ячеек

Статус: принято (этап 3). Связано: FR-API-01…10, FR-KYC-05, AS-23, AC-06…08, LR-19.

## Контекст

ТЗ требует серверную проверку entitlements на каждом запросе (FR-API-06),
профили полей `c1_basic`/`c1_full` без полей C1 на уровне схемы (AS-23) и
агрегаты с ячейками ≥ 30 магазинов (LR-19). Несколько моментов ТЗ не
уточняет: как трактовать пустой список стран/платформ в entitlement, что
отвечать на запрос магазина вне сегмента, и как показывать «малые» ячейки.

## Решения

1. **Пустой сегмент = без ограничений.** `entitlement.countries = []`
   означает все страны, `platforms = []` — все платформы. Ограничение
   задаётся только явным списком. Это упрощает контракты «вся Европа» и
   не требует перечислять 40+ стран.
2. **Вне сегмента — 403 `outside_segment`, не 404.** Клиент, запросивший
   магазин вне своих стран, получает 403 с `reason=outside_segment`: это
   честный ответ о границах контракта (FR-API-06 «понятный код ошибки»), а
   не утечка факта существования магазина: наличие домена в базе не является
   чувствительной информацией (домен публичен), тогда как 404 заставил бы
   клиента считать, что магазин не отсканирован.
   Фильтр `country=` вне сегмента тоже 403; без фильтра выдача автоматически
   сужается до сегмента.
3. **Невидимые домены — 404.** Домены только из CZDS, домены с opt-out и не
   e-commerce не существуют для клиента (`entitlements.lineage_guard.
   c1_visible_clause`): они отфильтрованы в каждом запросе, экспорте и
   агрегате одним и тем же SQL-предикатом. 404 здесь не раскрывает
   происхождение данных.
4. **Схема на профиль, а не фильтрация полей.** `StoreBasic`/`StoreFull`
   (`api/schemas/c1_basic.py`, `c1_full.py`) — отдельные Pydantic-модели с
   `extra="forbid"`; поля C1 (`third_party_hosts`, `plugins`, версии
   платформ/плагинов, внутренние скоры) есть только в `schemas/internal.py`,
   который используется исключительно админкой (`staff_analyst`).
   `response_model` FastAPI сериализует через эти модели, поэтому утечка
   невозможна без правки схемы; тест `test_api_access.py::test_c1_fields_
   never_serialised` и контрактный тест проверяют это по тексту ответа.
5. **Подавление ячеек (`/v1/stats/market-share`, отчёты).** Ячейка
   (страна × платформа) с < 30 магазинами не публикуется целиком
   (`withheld`), а провайдеры с < 30 магазинами внутри опубликованной ячейки
   объединяются в `other` (по множеству уникальных хостов, чтобы магазин с
   двумя редкими PSP не считался дважды). Порог `min_cell_size` возвращается
   в ответе, чтобы клиент мог объяснить пропуски.
6. **Rate limit и квоты.** Фиксированное окно 1 с по организации
   (`entitlements.quotas.RateLimiter`, Redis в проде, память в тестах),
   квота записей в сутки/месяц считается по `usage_log` (сумма `records`),
   проверяется до выполнения запроса; 429 с `Retry-After` и `code`
   `rate_limited` / `quota_exceeded`. Экспорт учитывается в тех же квотах.
7. **Ключи.** Формат `pik_<8 видимых>.<43 секретных>`; в БД — HMAC-SHA256 с
   pepper и видимый префикс для поиска; показывается один раз (FR-API-02).
   Контракт вне срока → 403 `contract_not_in_term`, активного entitlement нет
   → `no_entitlement`, организация не `active` → `org_not_active`.

## Последствия

- Все ответы 4xx — `application/problem+json` (RFC 9457) с полями `code`,
  `reason`; задокументированы в OpenAPI для каждой операции.
- Клиент не может отличить «домен не отсканирован» от «домен скрыт»; это
  сознательно (п. 3).
