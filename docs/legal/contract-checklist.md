# Чек-лист договора с клиентом (LR-09, LR-11, LR-15, LR-21)

Каркас для юриста: что обязано быть в договоре на доступ к данным
модуля C и чем это подкреплено в системе. Пункты со знаком ⚖ требуют
юридической формулировки, их в репозитории нет (ADR-0001, LR-23).

## 1. Предмет и роли (LR-09)

- [ ] Клиент получает доступ к агрегированной и профильной информации о
      платёжной инфраструктуре сайтов; персональные данные не являются
      предметом (методология: `docs/methodology.md`, лист «Methodology»).
- [ ] ⚖ Роли по GDPR: оператор — контролёр для собранных данных; клиент —
      самостоятельный контролёр для своего использования. DPA заключается,
      если клиент передаёт нам персональные данные своих сотрудников
      (e-mail пользователей портала) — ст. 28 GDPR.
- [ ] В системе: договор хранится как файл (`contract.file_key` в S3,
      `contracts/`), срок и цели — `contract.purposes`, `valid_until`
      (FR-KYC-05); пользователи клиента — `user.email`, роль (`membership`).

## 2. Допустимые цели и запреты (LR-15, LR-20)

- [ ] Закрытый перечень целей (из KYC-досье: `kyc_dossier.purposes`),
      любое другое использование — существенное нарушение.
- [ ] Запрет: перепродажа, публикация, деанонимизация, рассылки по
      контактам магазинов, использование против владельцев сайтов.
- [ ] Право оператора приостановить доступ немедленно (`suspend`/`restrict`
      → 403, FR-AB-03) и расторгнуть при нарушении; канарейки и водяные
      знаки (ADR-0018) как доказательство утечки — согласие клиента на их
      наличие в выгрузках.
- [ ] Журнал использования (`usage_log`) и аудит — как доказательная база.

## 3. Передача данных и размещение (LR-11)

- [ ] Данные размещаются в ЕС (Hetzner DE/FI), бэкапы — в ЕС.
- [ ] ⚖ Если клиент вне ЕС/ЕЭЗ — стандартные договорные условия (SCC,
      решение 2021/914, модуль «контролёр → контролёр») в приложении.
- [ ] Субпроцессоры оператора: хостинг (Hetzner), OpenSanctions (скрининг
      бенефициаров клиента), Telegram (доставка алертов), провайдер
      гео-прокси (без персональных данных клиента).

## 4. Оговорки о данных (LR-21)

- [ ] Данные — результат внешнего наблюдения: достоверность (`confidence`),
      неполнота, невидимый эквайер, задержка до 35 дней; никакие выводы о
      финансовом положении магазина не делаются (методология,
      `report.methodology` в экспортах).
- [ ] Данные не используются для принятия решений, имеющих юридические
      последствия для физических лиц (ст. 22 GDPR).

## 5. Срок, прекращение, удаление

- [ ] По окончании договора ключи API отзываются (`entitlement` истекает,
      FR-KYC-05), выгрузки у клиента — удаляются или возвращаются; срок
      хранения `usage_log`/`audit_log` у оператора — по RoPA.
- [ ] Повторный KYC раз в 12 месяцев и при смене бенефициаров (FR-KYC-06).

## 6. Контакты

- [ ] Ответственный за злоупотребления у оператора (runbook §22) и
      контакт по безопасности у клиента; срок реакции на инцидент — 72 ч.
